**Decision (2026-09-28) — deployment is manual, not git-automated.** Updates to a client's site
happen by hand — the developer edits code and uploads it themselves (FTP / cPanel File Manager /
manual `git pull` on the server); Codexehub does not connect to a client's git repo or push code to
their server automatically. **Phase 5 (Release Management), Phase 7 (Deployment), Phase 8 (cPanel
drivers), and `GIT-001`/`GIT-002` (Phase 4) are out of scope** — first descoped-but-kept-as-a-record
on 2026-09-28, then **removed from this file entirely on the same date** at the developer's explicit
instruction (they added no value sitting unticked; this decision note is the record of why they
existed and why they're gone — reintroduce them from the SRS/checklist history, not by un-deleting a
stub, if a future self-service/automated tier revives this scope). **License/package sync stays in
scope** (Phase 6 Vendor Client & Sync, Phase 9 License Enforcement `LIC-001..007`) — installation
registration, heartbeat, and package/feature entitlement sync are about what a customer is licensed
for and whether their license is valid, not about deploying code, so a client's "My Package" screen
and non-payment site-lock still need to work with zero deploy automation. `GA-E2E-001`'s
"develop → … → deploy → validate → activate" step is now a manual upload, not a pipeline stage.
